# 术语澄清：模型 / harness / 安全机制 / "臂"

> 一句话：**"臂"（arm）不是换模型，也不是换 harness；它是"同一批任务、同一模型、同一 harness、同一评测器下，只改一个实验条件"的一组运行。**
> 我们的实验里，**变的是安全机制配置（yaml），不变的是模型和 harness。**

## 1. 三层东西，先分清楚

```
┌─────────────────────────────────────────────────────────────┐
│ ① 模型（LLM）：deepseek-chat（Flash）                         │
│    负责"想 + 说话"                                            │
├─────────────────────────────────────────────────────────────┤
│ ② harness / agent scaffold：我们自研的 builtin agent          │
│    负责"读文件、改文件、何时停止"（工具协议、步数、截止线）      │
│    SusVibes 官方模板是 SWE-agent / Claude Code / OpenHands /  │
│    Kimi CLI —— 我们没用它们，自己写了一个                      │
├─────────────────────────────────────────────────────────────┤
│ ③ 安全机制层（我们的贡献）：M1 知识 / M2 检测 / M3 控制        │
│    插在 ② 外面：改题面、判安全、决定重做/阻断                  │
├─────────────────────────────────────────────────────────────┤
│ ④ 评测器：SusVibes 官方 susvibes.eval.core（FuncPass/SecPass）│
│    固定不动，所有臂一样                                        │
└─────────────────────────────────────────────────────────────┘
```

**SusVibes 把 ① 和 ② 分开**：同一个模型可以配不同 harness；同一个 harness 可以换模型。
所以"把 Kimi/Claude Code 换成 DeepSeek"这个说法不准确：**我们换的是 harness（自研 builtin）和模型（DeepSeek），但在所有臂里这两件事都不变**。

## 2. "臂"是什么

| 实验设计 | 臂 = 什么 | 数量 |
|---|---|---|
| **8 臂因子实验** | M1/M2/M3 **开/关**的 2×2×2 组合 | 8 个：`000/100/010/001/110/101/011/111` |
| **48 组配方实验** | 每个机制**选一种策略**：M1(3) × M2(4) × M3(4) | 48 个：`recipes/01–48` |

例子：
- `011` = 不做知识 + 开检测 + 开控制（核心闭环）；
- `recipes/01` = K1 通用知识 + L1 自审 + F/C 反馈与重做。

**每个"臂"就是一个 yaml 配置**：`harness_sec/configs/011.yaml` 或 `recipes/01.yaml`。

## 3. 变量表：什么固定、什么变

| 项 | 8 臂 / 48 组（内部对比） | 官方策略对照（外部对比） | 与论文/榜单比 |
|---|---|---|---|
| 任务 | **同一批** `tasks_8.json` | 同一批 | 不同（186 全量） |
| 模型 | deepseek-chat | deepseek-chat | Claude 4 Sonnet 等 |
| harness | 自研 builtin | 自研 builtin | SWE-agent 等 |
| 安全机制 | **变（yaml）** | 官方题面策略（generic/self-selection/oracle） | 官方策略 |
| 评测器 | 官方 | 官方 | 官方 |
| 回答 | 机制组合有没有效 | 比现有策略好吗 | **只作背景，不可直接比** |

## 4. 三种对比，别混

1. **内部对比（我们的臂 vs 我们的臂）**：只换安全机制 → 公平 → 论文主结论（8 臂主效应/交互，48 组排名/边际效应）。
2. **外部对比（我们的机制 vs SusVibes 现有策略）**：同任务/同模型/同 harness/同评测，只把"题面"换成官方 `generic`/`self-selection`/`oracle` → 回答"比现有策略强吗"。
3. **与论文/榜单对比**：scaffold、模型、预算都不同（60 步 vs ~200 次调用；Flash vs Claude）→ **不可直接比**，只能引用作背景，并注明差异。

## 5. 为什么不用官方 SWE-agent / Kimi CLI 跑我们的实验

- 我们的 M2/M3 需要"在 agent 和评测器之间"插逻辑（判安全 → 反馈 → 重做/阻断）；官方 harness 是"单次生成 + 导出 patch"，没有这些钩子，硬接成本高；
- 384 次运行需要可控预算（步数/重试/成本）和断点续跑，自研 scaffold 更容易；
- **代价**：绝对数字不能跟榜单比 → 必须写 Setup + 做 scaffold 校准（见 `docs/BUDGET.md` §4）。

## 6. 四个常见误解

| 误解 | 事实 |
|---|---|
| "臂 = 换模型" | ❌ 所有臂同一个模型 |
| "臂 = 换 harness" | ❌ 所有臂同一个 harness |
| "我们在替换 SusVibes 的 agent 框架" | 我们只是**没采用**官方模板，另写了一个；不是替换上游代码 |
| "我们的数字可以直接和论文 Table 3 比" | ❌ scaffold/模型/预算都不同，只能比"我们的臂之间" |
