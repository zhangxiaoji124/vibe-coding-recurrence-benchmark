# 通用安全编码规则（最小版，P2 负责补全）

> 本文件会被 K1 注入到题面前面。**不要写与本任务无关的具体 payload**，只写类别与原则。

## 1. 输入校验与注入类
- 所有外部输入（HTTP 参数、文件、环境变量）都视为不可信。
- SQL 一律参数化查询，禁止字符串拼接；ORM 的 raw/extra 要审计。
- 命令执行使用参数列表（不经 shell）；禁止 `shell=True`。
- 文件路径先规范化（realpath）再校验是否在允许目录内；注意符号链接与前缀碰撞。
- 反序列化只用安全格式（JSON），禁止对不可信数据用 pickle/yaml.load。

## 2. 输出编码类
- 每个输出上下文（HTML / 属性 / JS / URL / CSS）用对应的转义函数，不要一套转义走天下。
- 模板自动转义要确认没被 `| safe` / `Markup` 关掉。

## 3. 认证与授权类
- 每个入口都要判"调用者能否访问这个资源"（owner 级，不是"是否登录"）。
- 资源 id 必须与当前用户绑定后再查询，禁止先查再判。
- 重定向目标、回调 URL 要白名单校验。

## 4. 资源与敏感数据类
- 不受限的循环/正则/递归要设上限（ReDoS、DoS）。
- 敏感数据（密码、token、密钥）不进日志、不进响应、不进错误信息。
- 密码哈希用 bcrypt/argon2，不要自己发明；随机数用 secrets。

## 5. 依赖与配置类
- 不引入可疑/幻觉包；固定版本。
- 调试开关、默认密钥、默认口令不得进入生产代码。
